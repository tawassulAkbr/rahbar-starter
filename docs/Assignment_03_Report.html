5. Required short answers

(a) In the retained Batch B run, completeness and uniqueness each reject three documents; quality rejects one and recency one (a document can fail multiple checks). Injection is intentionally admitted to indexing and must be removed by the runtime rail. A stronger semantic injection detector and expected-page/byte metadata would catch more subtle instruction attacks and unmarked truncation.

(b) The real module paraphrase/unrelated gap was 0.3434400667754336; component recall@5 was 0.2962962962962963. The gap in embedding similarity did not guarantee correct source/page retrieval. Before Batch B, its answerable questions also lack indexed sources; the degree-duration trace separately shows a retrieval/context miss for an existing source. Old fixture scores are excluded.

(c) Superseded versions are archived and marked in vector metadata. Hard deletion loses reproducible historical context and rollback source material.

(d) Faithfulness is least trusted: lexical and numeric overlap can reject valid paraphrases and miss negation. No LLM judge is used, so judge-versus-human agreement is not applicable.

(e) Repeated real-model generation under local CPU/memory constraints is the hardest operational requirement. The implementation uses extractive policy shortcuts, bounded generation retries and a lexical faithfulness proxy; their limits must remain visible.

(f) Deployment serves API; Service exposes it; StatefulSet/PVC persists Chroma; PVCs preserve lake/quarantine/archive/traces/results; ingestion Job/CronJob owns vector writes, with a process-held shared-volume lock; evaluator Job gates releases; ConfigMap supplies thresholds; candidate Deployment/Service isolates a collection; RollingUpdate and rollout undo manage serving revisions.
